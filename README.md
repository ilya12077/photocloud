# Photocloud

Веб-галерея фото и видео, которые лежат на домашнем Windows-ПК, и бэкап этого архива на другой компьютер.
Рассчитана на десятки тысяч файлов и медленный интернет у того, кто смотрит.

## Архитектура

```
 Windows-ПК (файлы)          сервер (Home Assistant, Docker)               интернет
┌──────────────────┐ SMB  ┌──────────────────────────────────┐  HTTPS  ┌─────────────────────┐
│ общая папка «фото»│◄────│ photocloud (FastAPI, порт 8099)  │◄─ NPM ─│ браузер: сайт/админка│
│ только чтение     │     │  индекс в памяти, эскизы на лету │         └─────────────────────┘
└────────▲─────────┘     │  SQLite + JSON в томе /data      │         ┌─────────────────────┐
         │ WoL           └───────┬──────────────────────────┘◄─ NPM ─│ клиент бэкапа (Win) │
         └──── Home Assistant ◄──┘ пробуждение ПК, уведомления         │ трей + окно, копия   │
                                                                     └─────────────────────┘
```

- **ПК** — только хранит файлы. Сервер читает их по SMB под пользователем «только чтение». Выключенный ПК будится кнопкой через скрипт WoL в Home Assistant, сам сервер его не будит.
- **Сервер** (`app/`) — один процесс FastAPI:
  - `library.py` — индекс: обход папок (имена, размеры, даты изменения), затем в фоне даты съёмки, подробности (камера, GPS), хеши для бэкапа;
  - `storage.py` — SMB с приоритетами (просмотр важнее фоновых задач), переподключение, защита от зависшего ПК;
  - `images.py`, `video.py`, `transcode.py` — эскизы и превью WebP на лету, кадры видео и HLS 720p через ffmpeg; всё только в RAM;
  - `auth.py`, `google_auth.py` — пользователи, сессии, доступ к папкам, вход через Google;
  - `backup.py` и `/api/backup/*` — токены и API для клиента бэкапа;
  - `static/` — сайт и админка (чистый JS, без сборки).
- **Данные сервера** (том `/data`): `photocloud.db` (SQLite: сессии, даты, подробности, адреса, хеши, токены бэкапа), `users.json`, `settings.json`, `audit.log`. Фото на сервер не копируются.
- **Клиент бэкапа** (`backup/photocloud_backup.pyw`) — один файл на Python для Windows: значок в трее и окно, своя SQLite в папке бэкапа. Сам ходит на сервер по HTTPS, поэтому работает и из-за NAT.

## Запуск

### Сервер (Docker / Portainer)

1. **На ПК с Windows**: создать локального пользователя, например `photoviewer`, с длинным паролем. Расшарить папку с фото: Свойства → Доступ → Расширенная настройка → Разрешения: `photoviewer` — только «Чтение», «Все» — убрать. В брандмауэре разрешить TCP 445 только с IP сервера:
   `New-NetFirewallRule -DisplayName "SMB from HA" -Direction Inbound -Protocol TCP -LocalPort 445 -RemoteAddress <IP_HA> -Action Allow -Profile Private`
2. **Portainer → Stacks → Add stack**: `docker-compose.yml` из репозитория, сборкой или с готовым образом `ilya1207/photocloud:latest`. Переменные окружения задаются в Portainer, в репозиторий не попадают:

   | Переменная | Что это |
   |---|---|
   | `SMB_HOST`, `SMB_SHARE`, `SMB_SUBDIR` | IP компа, имя шары, подпапка (необязательно) |
   | `SMB_USER`, `SMB_PASSWORD` | пользователь «только чтение» |
   | `ALLOWED_ORIGINS` | `https://<ваш домен>` |
   | `TRUSTED_PROXIES` | адрес NPM, по умолчанию `172.30.32.0/23,127.0.0.1/32` |
   | `HA_TOKEN`, `HA_WAKE_SERVICE` | токен HA и `script.<ваш_wol>` |
   | `HA_NOTIFY_SERVICE` | `notify.mobile_app_<телефон>` (необязательно) |
   | `PUBLIC_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | вход через Google (необязательно) |

3. **NPM**: Proxy Host на IP Home Assistant, порт `8099`, SSL + Force SSL; в Advanced:
   ```nginx
   proxy_set_header X-Real-IP $remote_addr;
   proxy_buffering off;
   proxy_read_timeout 120s;
   client_max_body_size 64k;
   ```
4. В логах контейнера появится одноразовая ссылка `…/admin#setup=…`. Открыть её через свой домен и создать администратора. В «Сессиях» админки должен быть виден ваш внешний IP. Если там `172.30.x.x` или сайт отвечает 403, поправить `TRUSTED_PROXIES`.

Образы собирает GitHub Actions при изменении файла `VERSION`: из `master` — теги `<версия>` и `latest`, из ветки `backup-cluster` — только тег `backup-cluster`. Версия видна в «Обзоре» админки и в лейбле `org.opencontainers.image.version`. Portainer при «Recreate» переносит в контейнер старые лейблы и переменные, поэтому обновлять удобнее через стек.

### Тест на своём компьютере

```
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements.txt
python -m app
```
Первый запуск создаст `.env` из `.env.example`. В нём указать `STORAGE=local` и `LOCAL_ROOT=<папка с фото>`, затем запустить снова и перейти по ссылке `http://localhost:8099/admin#setup=…` из консоли.

### Клиент бэкапа (Windows)

1. Админка → «Бэкап» → «Новый клиент»: название и пользователь, чьи папки копировать. Токен показывается один раз.
2. Нужен только один файл — [`backup/photocloud_backup.pyw`](backup/photocloud_backup.pyw) — и Python 3.11+. Двойной щелчок; недостающие библиотеки (httpx, pystray, pillow) программа предложит поставить сама, в тот же Python.
3. «Настройки»: адрес сайта, токен, папка бэкапа → «Сохранить». Галочки: автозапуск при входе в Windows, запуск без окна (только значок в трее), проверка обновлений.

Настройки, журнал `backup.log` и служебные файлы — в `%USERPROFILE%\.photocloud-backup` (не в `%APPDATA%`: Python из Microsoft Store прячет записанное туда в свою песочницу).

## Использование

**Сайт.** Папки и лента по месяцам. Размер плиток меняется щипком или Ctrl+колесо. Фото открывается сразу быстрым превью, следом подгружается оригинал («Без сжатия •»). Жесты в просмотре:
- вбок — листать;
- вниз — закрыть;
- вверх или колесо вниз на компьютере — «Подробнее»: дата и откуда она взята, камера, размер, карта и адрес по GPS.

Живые фото проигрываются касанием. Видео идёт в 720p с перекодированием на лету, галочка «Оригинал» включает исходный файл. Если ПК выключен, есть кнопка «Запустить компьютер», если пользователю это разрешено.

**Админка** (`/admin`):
- «Обзор» — состояние ПК и индекса, пересканирование;
- «Пользователи» — роли, доступ к папкам, право включать ПК, Google;
- «Сессии» и блокировки IP;
- «Бэкап» — клиенты и их ход, хеши, проверка;
- «Настройки» — уведомления, сервисы HA, интервалы;
- «Скорость» — замеры эскизов;
- «Журнал».

Открытая вкладка обновляется сама. Папки пересканируются раз в 10 минут, после включения ПК и по кнопке.

**Бэкап.** В папке бэкапа:
- `Архив\` — копия один в один, с путями и датами как на ПК;
- `Версии\` — прежние варианты изменённых файлов и повреждённые копии;
- `Удалённые\` — то, что удалили на ПК;
- `.photocloud-backup\` — база клиента и недокачанные файлы.

Из «Версий» и «Удалённых» клиент ничего не удаляет.

Как работает клиент:
- Запускается, будит ПК (если разрешено) и раз в 10 секунд спрашивает сервер о новом. Пока ПК выключен, ждёт.
- Качает с докачкой, сверяет SHA-256 и сжимает блоки там, где это даёт выигрыш.
- Переименования и переносы повторяет у себя без скачивания.
- Копию, удалённую из папки бэкапа, снова скачивает в течение минуты.

Управление — в окне и в меню значка в трее (правая кнопка):
- пауза и лимит скорости;
- «Проверить сейчас»;
- «Разбудить ПК»;
- порог свободного места, ниже которого новые файлы не качаются.

Защита и проверки:
- Если сервер прочитал не все папки или с ПК разом пропало больше 100 файлов (и больше 5% от скопированного), клиент ничего не убирает в «Удалённые» без кнопки «Подтвердить».
- Раз в 30 дней хеши сверяются заново, и это же можно запустить кнопкой: сервер перечитывает файлы с ПК, клиент — свои копии. Дата проверки каждого файла хранится в базе, прерванная проверка продолжается с того же места. Файл, тихо изменившийся на ПК, и испорченная копия скачиваются заново, старый вариант уходит в «Версии».
- Обновления клиент ищет сам: раз в 6 часов сравнивает свою строку `VERSION = "…"` с той же строкой файла в последнем коммите ветки на GitHub (`master`, можно сменить в настройках), предлагает обновиться, подменяет себя новым файлом и перезапускается. Файл `backup/VERSION` нужен только старым клиентам (до 1.3.0) и держится равным этой строке.

## Безопасность

- Браузер не видит путей к файлам, только непрозрачные id. Доступ к папкам проверяется на сервере в каждом запросе: чужой файл отвечает 404, как несуществующий. Ярлыки, junction, скрытые и системные файлы не индексируются.
- Пароли хранятся в argon2id. 5 неудачных входов с IP — блокировка на 15 минут и уведомление. В базе лежат только SHA-256 сессий и токенов бэкапа. Cookie `HttpOnly; Secure; SameSite=Strict; __Host-`.
- От CSRF защищают спец-заголовок и проверка Origin. Строгий CSP без inline-скриптов, запрет фреймов, `no-referrer`. Первый администратор создаётся только по одноразовой ссылке из консоли.
- ffmpeg запускается с явным демуксером и белым списком протоколов. Есть защита от «бомб» распаковки и лимиты на размер запросов. Прямые запросы мимо прокси получают 403.
- Контейнер работает от пользователя без прав, файловая система только для чтения, кроме `/data`, все capabilities сброшены. Токен клиента бэкапа хранится зашифрованным средствами Windows (DPAPI).
- Репозиторий публичный: `.env`, `data/` и журналы в `.gitignore`, в примерах только типовые адреса.
