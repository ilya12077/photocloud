# Photocloud

Веб-галерея фото- и видеоархива, хранящегося на домашнем Windows-ПК, и инкрементальный бэкап этого архива на удалённый компьютер с контролем целостности (SHA-256). Рассчитана на 10⁴–10⁵ файлов и узкий канал у клиента.

## Архитектура

```
 Windows-ПК                 сервер (Home Assistant, Docker)                 интернет
┌──────────────────┐ SMB  ┌──────────────────────────────────┐  HTTPS  ┌──────────────────────┐
│ шара «фото» (R)   │◄────│ photocloud: FastAPI, порт 8099    │◄─ NPM ─│ браузер: сайт, админка│
│ Restored\ (W)     │◄────│ индекс в RAM, эскизы/HLS на лету  │         └──────────────────────┘
└────────▲─────────┘     │ SQLite + JSON в томе /data        │         ┌──────────────────────┐
         │ WoL           └───────┬───────────────────────────┘◄─ NPM ─│ клиент бэкапа (.pyw)  │
         └──── Home Assistant ◄──┘ пробуждение, уведомления           └──────────────────────┘
```

- **ПК** хранит файлы. Сервер читает их по SMB под пользователем только для чтения; пишет единственный раз — восстановленные копии в `Restored`, под отдельным пользователем. ПК будится по запросу (WoL через HA), автоматически — нет.
- **Сервер** (`app/`, версия — `app/VERSION`):
  - `library.py` — индекс (имя, размер, mtime), затем в фоне: дата съёмки, EXIF (камера, GPS), SHA-256 для бэкапа, ежемесячная сверка хешей;
  - `storage.py` — SMB-клиент с приоритетами, переподключением и сторожем зависаний; `RestoreWriter` — запись в `Restored`;
  - `images.py`, `video.py`, `transcode.py` — WebP-эскизы и HLS 720p через ffmpeg, в RAM; исключение — самый маленький эскиз видео: он сохраняется в базу, когда лента впервые его посчитала (или кнопкой «Посчитать эскизы видео» в админке), и дальше отдаётся без ПК и без ffmpeg; лишние записи удаляются при сканировании папок. Файлы без видеодорожки (диктофонные `.3gp`) в ленте не показываются: это выясняется при первой попытке взять кадр и запоминается в базе;
  - `auth.py`, `totp.py` — пользователи, сессии, доступ к папкам, двухфакторный вход;
  - `backup.py` и `/api/backup/*` — токены и API клиента бэкапа;
  - `static/` — сайт и админка (JS без сборки).
- **Данные сервера** (`/data`): `photocloud.db` (сессии, даты, EXIF, адреса, хеши, повреждённые файлы, токены, маленькие эскизы видео), `users.json`, `settings.json`, `audit.log`. Медиафайлы на сервер не копируются.
- **Клиент бэкапа** — один файл `backup/photocloud_backup.pyw` (версия — строка `VERSION` в нём): трей и окно, собственная SQLite в папке бэкапа. Инициирует все соединения сам, поэтому работает из-за NAT и может подолгу быть офлайн.

## Запуск

### Сервер

1. **ПК.** Локальный пользователь `photoviewer` с длинным паролем; общий доступ к папке с фото: `photoviewer` — «Чтение», «Все» — убрать. Входящий TCP 445 — только с IP сервера:
   ```powershell
   New-NetFirewallRule -DisplayName "SMB from HA" -Direction Inbound -Protocol TCP -LocalPort 445 -RemoteAddress <IP_HA> -Action Allow -Profile Private
   ```
2. **Восстановление (необязательно).** Пользователь с правом записи только в `Restored` и отдельная скрытая шара на эту папку; к основной шаре у него доступа нет. PowerShell от администратора:
   ```powershell
   $share = (Get-SmbShare -Name "фото").Path            # имя основной шары
   $pw = Read-Host -AsSecureString "Пароль для photorestore"
   New-LocalUser -Name "photorestore" -Password $pw -PasswordNeverExpires -AccountNeverExpires -Description "photocloud: запись только в Restored"
   New-Item -ItemType Directory -Path "$share\Restored" -Force | Out-Null
   icacls "$share\Restored" /grant "photorestore:(OI)(CI)M"
   New-SmbShare -Name 'photo-restored$' -Path "$share\Restored" -ChangeAccess "photorestore"
   Get-SmbShareAccess -Name 'photo-restored$'          # только photorestore
   Get-SmbShareAccess -Name "фото"                      # photorestore здесь быть не должно
   ```
   Если у основной шары в доступе есть `Everyone` или `Users` — заменить на явного `photoviewer` (Read): `photorestore` не должен попадать в неё ни напрямую, ни через группы.
3. **Portainer → Stacks**: `docker-compose.yml`, образ `ilya1207/photocloud:latest`. Переменные:

   | Переменная | Значение |
   |---|---|
   | `SMB_HOST`, `SMB_SHARE`, `SMB_SUBDIR` | IP ПК, шара, подпапка (необяз.) |
   | `SMB_USER`, `SMB_PASSWORD` | пользователь только для чтения |
   | `SMB_RESTORE_USER`, `SMB_RESTORE_PASSWORD`, `SMB_RESTORE_SHARE` | `photorestore`, пароль, `photo-restored$` (необяз.) |
   | `ALLOWED_ORIGINS` | `https://<домен>` |
   | `TRUSTED_PROXIES` | адрес NPM, по умолч. `172.30.32.0/23,127.0.0.1/32` |
   | `HA_TOKEN`, `HA_WAKE_SERVICE`, `HA_NOTIFY_SERVICE` | токен HA, `script.<wol>`, `notify.<телефон>` |
   | `PUBLIC_URL` | внешний адрес — для ссылки первичной настройки в логе (необяз.) |

   Остальное — необязательно, см. «Настройки сервера».

4. **NPM** → Proxy Host на HA:8099, SSL + Force SSL, Advanced:
   ```nginx
   proxy_set_header X-Real-IP $remote_addr;
   proxy_buffering off;
   proxy_read_timeout 120s;
   client_max_body_size 16m;
   ```
   16 МБ нужны для загрузки восстановленных копий (куски по 8 МБ); остальные эндпоинты ограничивают тело сами (4–8 КБ, ответ 413 по `Content-Length` до чтения).
5. Одноразовая ссылка `…/admin#setup=…` из логов контейнера → создать администратора. В «Пользователях» (активные сессии) должен быть внешний IP; если `172.30.x.x` или 403 — поправить `TRUSTED_PROXIES`.

Образ собирает GitHub Actions при изменении `app/VERSION`: `master` → теги `<версия>` и `latest`; ветка `beta` → только тег `beta` (для проверки нового до выпуска). Обновлять — «Update the stack» с «Re-pull image» (Recreate в Portainer сохраняет старые лейблы и переменные).

**Локальный тест:** `pip install -r app/requirements.txt && python -m app` — создаст `.env`; указать `STORAGE=local`, `LOCAL_ROOT=<папка>`.

### Клиент бэкапа

1. Админка → «Бэкап» → «Новый клиент»: название и пользователь, чьи папки копируются. Токен показывается один раз.
2. Python 3.11+ и файл `backup/photocloud_backup.pyw`; недостающие httpx, pystray, pillow клиент предложит установить сам.
3. «Настройки»: адрес, токен, папка → «Сохранить»; автозапуск (с задержкой 30 с), запуск без окна, обновления.

Настройки и журнал — `%USERPROFILE%\.photocloud-backup` (`%APPDATA%` у Python из Microsoft Store виртуализирован).

## Настройки сервера

Переменные окружения (в Portainer — «Environment variables»). Секреты можно передать и файлом: `ИМЯ_FILE=/путь` (docker secrets). Неверное значение — сервер не стартует и пишет причину в лог. Помеченное * меняется и в админке («Настройки»); значение из админки важнее переменной.

| Переменная | По умолч. | Что задаёт |
|---|---|---|
| **Подключение к ПК** | | |
| `SMB_PORT` | `445` | порт SMB |
| `SMB_ENCRYPT` | `true` | шифрование SMB 3 (в локалке можно `false` — меньше нагрузка; подпись остаётся) |
| `STORAGE`, `LOCAL_ROOT` | `smb` | `local` + папка — без ПК, для теста |
| **Home Assistant** | | |
| `HA_URL`, `HA_VERIFY_SSL` | `http://127.0.0.1:8123`, `true` | адрес HA и проверка его сертификата |
| `HA_WAKE_SERVICE`, `HA_WAKE_DATA` | — | сервис включения ПК и его данные (JSON); только `script.…`, `button.press` или `wake_on_lan.send_magic_packet`, в админке не меняется |
| `WAKE_TIMEOUT`* | `180` | с: сколько ждать, пока ПК проснётся |
| `HA_NOTIFY_SERVICE`*, `NOTIFY_EVENTS`* | события ниже | уведомления: `login`, `login_new_ip`, `login_failed`, `lockout`, `wake`, `wake_timeout`, `index_error`, `backup_stale`, `damaged` |
| `BACKUP_STALE_DAYS`* | `7` | дней без связи с клиентом бэкапа до уведомления (0 — не следить) |
| **Сеть и вход** | | |
| `PORT`, `BIND` | `8099`, `127.0.0.1` | порт и адрес (в контейнере — все адреса) |
| `TRUSTED_PROXIES`, `REQUIRE_PROXY` | см. выше, `true` | откуда принимать запросы (остальным — 403) |
| `COOKIE_SECURE` | `true` | cookie только по HTTPS (`false` — только для теста по http) |
| `SESSION_IDLE_HOURS`*, `SESSION_MAX_HOURS` | `168`, `720` | с «Запомнить вход»: выход при бездействии / максимум жизни сессии, ч |
| `SESSION_SHORT_MINUTES`* | `15` | без «Запомнить вход» (по умолчанию): выход при бездействии, мин; cookie сеансовая. Фоновый опрос открытой вкладки бездействие не прерывает |
| `PUBLIC_NAME`* | `Фотоархив` | название сайта |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс для дат съёмки без пояса |
| **Сканирование и ресурсы** | | |
| `INDEX_TTL`* | `600` | с: как часто пересканировать папки |
| `WORKERS` | ядер + 1 (2…8) | потоки эскизов и превью |
| `META_THREADS` | `4` | потоки чтения дат и EXIF |
| `TRANSCODE`, `TRANSCODE_SLOTS` | `true`, `2` | перекодирование видео в HLS и сколько ffmpeg одновременно (по 1 потоку) |
| `TRANSCODE_CACHE_MB` | `256` | кэш перекодированного видео в памяти |
| `THUMB_CACHE_MB`, `PREVIEW_CACHE_MB` | `128`, `64` | кэш эскизов и превью в памяти (0 — без кэша) |
| `MAX_DECODE_MB` | `150` | предел картинки, Мп: больше — не распаковывается (защита от «бомб») |
| `FFMPEG` | системный | путь к ffmpeg |
| **Эскизы и превью** | | |
| `IMAGE_FORMAT` | `webp` | `webp` или `jpeg` |
| `THUMB_SMALL_SIZE`, `THUMB_SIZE`, `THUMB_LARGE_SIZE` | `240`, `400`, `900` | эскизы, px |
| `THUMB_QUALITY` | `60` | качество эскизов |
| `PREVIEW_QUICK_SIZE`, `PREVIEW_QUICK_QUALITY` | `720`, `32` | быстрое превью |
| `PREVIEW_SIZE`, `PREVIEW_QUALITY` | `2048`, `72` | превью при просмотре |
| `DATA_DIR` | `/data` | где база, пользователи, журнал |

Зашито в коде (меняется только правкой): хеши — 3 потока, чтение кусками по 4 МБ (`library.py`, `main.py`); к ПК по SMB — не больше 6 запросов одновременно, из них фоновых (даты, хеши) не больше 4 (`storage.py`); проверка хешей — раз в 30 дней.

### Контейнер: защита и ресурсы

- **Образ** (`Dockerfile`): процесс работает от пользователя `photocloud` (UID 10001), не от root.
- **Стек** (`docker-compose.yml`, блок «защита контейнера») — действует, только если эти строки есть в стеке Portainer:

  | Строка | Что даёт |
  |---|---|
  | `read_only: true` | файловая система только для чтения; писать можно лишь в `/data` (том) и `/tmp` |
  | `tmpfs: /tmp:size=64m` | временные файлы — в памяти, до 64 МБ |
  | `cap_drop: [ALL]` | никаких привилегий ядра (сеть, файлы чужих пользователей, монтирование…) |
  | `security_opt: no-new-privileges` | нельзя получить права через setuid-программы |
  | `mem_limit: 1536m` | не больше 1,5 ГБ памяти |
  | `pids_limit: 256` | не больше 256 процессов и потоков |
  | `logging … 10m × 3` | логи — не больше 30 МБ |

  Процессор не ограничен; чтобы ограничить — `cpus: 2` (не больше двух ядер). Проверка: Portainer → контейнер → Inspect → `HostConfig`: `ReadonlyRootfs: true`, `CapDrop: ["ALL"]`, `Memory: 1610612736`.
- **Сеть**: `network_mode: host` — контейнер видит ПК в локалке и HA на 127.0.0.1; запросы не через NPM (`TRUSTED_PROXIES`) получают 403.

### Клиент бэкапа

Всё — в окне программы, хранится в `%USERPROFILE%\.photocloud-backup\config.json`; токен там зашифрован DPAPI (функции `protect`/`unprotect`): расшифровать может только та же учётная запись Windows на том же ПК.

| Настройка | По умолч. | Что задаёт |
|---|---|---|
| Адрес сайта, токен, папка бэкапа | — | куда подключаться и куда копировать |
| Одновременных загрузок | 3 (1–6) | сколько файлов качать сразу |
| Лимит скорости | 0 — без лимита | Мбит/с на все загрузки вместе |
| Оставлять свободным | 10 ГБ | меньше — новые файлы не качаются |
| Будить ПК при запуске | да | |
| Автозапуск, без окна при автозапуске | да, да | старт через 30 с после входа в Windows |
| Обновления, ветка | да, `master` | проверка раз в 6 ч |

Зашито в коде: опрос сервера — раз в 10 с; обрыв — если данные не идут 30 с; проход — не дольше 15 мин (потом свежий список); проверка копий — раз в 30 дней; удаления ждут «Подтвердить», если пропало больше 100 файлов и больше 5 %.

## Использование

**Сайт.** Папки и лента по месяцам; масштаб плиток — щипок, Ctrl+колесо. Просмотр: превью 720 → 2048 → оригинал; жесты: вбок — листать, вниз — закрыть, вверх (колесо вниз) — «Подробнее»: дата и её источник, EXIF, карта и адрес по GPS; щипок или двойное касание — увеличить (двойное касание ещё раз — вернуть). Живые фото — касанием. Видео (в т.ч. MTS, AVI, MPG, VOB) — HLS 720p на лету, «Оригинал» — исходный файл.

**Личное: избранное, скрытые, группы.** У каждого пользователя своё, другим не видно; файлы на ПК не трогаются, бэкап не меняется. Выбор фото: на телефоне — долгое нажатие, дальше касания или протягивание пальцем (у края экрана лента едет сама); на компьютере — меню ⋯ → «Выбрать фото» или зажать левую кнопку на фото (дальше можно вести мышью), клик, Shift+клик — всё между двумя фото (если предыдущее сняли — снимает). Сверху — «✕ Выбрано N» и действия:
- ☆ — в избранное; меню ⋯ → «Избранное» (`/starred`) — та же галерея только с ними;
- скрыть — пропадает из галереи только у тебя; меню ⋯ → «Скрытые фото» (`/hidden`), там «вернуть в галерею»;
- сгруппировать (два квадратика) — в ленте остаётся первое выбранное со значком и числом, нажатие раскрывает группу на месте; «Разгруппировать» — разобрать;
- «удалить окончательно» (корзина с крестиком, только админ, на `/hidden`, только своё скрытое) — пока пометка в базе (`delete_marks`: путь, ключ и хеш файла на момент пометки, кто, когда); помеченное пропадает и из скрытых; удалять с ПК будет отдельный клиент на ПК.

В базе — таблицы `starred`, `user_hidden`, `user_groups` (пользователь, путь…); в памяти — наборы путей, списки пересобираются только после изменений.

**Двухфакторный вход** включает админ: «Пользователи» → колонка 2FA → «включить». При следующем входе (после пароля) пользователь видит QR-код и ключ для Google Authenticator (Яндекс Ключ, Microsoft Authenticator…), добавляет аккаунт и вводит код — дальше при каждом входе спрашивается 6-значный код. Потерян или сменён телефон — «новый телефон» в админке или из консоли контейнера (Portainer → контейнер → Console) `python -m app 2fa-reset <логин>`: при следующем входе настройка заново; `python -m app 2fa-off <логин>` — выключить. Работающий сервер подхватывает это сам.

**Админка** (`/admin`): обзор и пересканирование (авто — раз в 10 мин и при включении ПК), пользователи с доступом к папкам, сессиями и блокировками IP, бэкап, скорость, настройки, журнал. Открытая вкладка обновляется сама.

**Бэкап.** Структура папки: `Архив\` — зеркало ПК (пути и mtime), `Версии\` — прежние и повреждённые варианты, `Удалённые\` — удалённое на ПК, `.photocloud-backup\` — база и недокачанное. Из `Версий` и `Удалённых` ничего не удаляется.
- Опрос сервера — раз в 10 с; загрузка с докачкой, проверкой SHA-256, блочным сжатием (zlib, если выигрыш ≥ 3 %), лимитом скорости (на все загрузки вместе) и порогом свободного места; по умолчанию 3 файла одновременно (настройка 1–6 в окне).
- Переименования и переносы на ПК распознаются по хешу и выполняются без скачивания.
- «Получить список файлов» — свежий список и обход папки: копии из базы — по размеру, прочие файлы — по хешу; «Проверить хеши» — пересчёт хешей всех копий (и автоматически раз в 30 дней). Пропавшие копии докачиваются, посторонние файлы уходят в `Удалённые`.
- Массовое исчезновение (> 100 файлов и > 5 %) или неполный индекс сервера — удаления ждут «Подтвердить».
- Пауза останавливает сеть и дисковые операции; прерванное продолжается с того же места.
- Обновление: раз в 6 ч сравнение `VERSION` с последним коммитом `master`, замена файла, перезапуск.

**Повреждённые файлы на сервере.** Раз в 30 дней (и по кнопке) сервер перечитывает файлы и сверяет SHA-256. Несовпадение при прежних размере и mtime, либо ошибка чтения, трактуется как порча: эталоном остаётся прежний хеш, клиенты испорченную версию не скачивают. Первый клиент, вышедший на связь с правильной копией (запрос ждёт его сколько угодно), передаёт её; сервер проверяет хеш, пишет в `Restored\<тот же путь>` с mtime оригинала, перечитывает и сверяет. После переноса копии на место оригинала (с заменой) сервер фиксирует исправление. «Это не порча» в админке принимает текущую версию как эталон. Все этапы — в журнале и уведомлениях HA.

## Безопасность

- Браузер оперирует непрозрачными id, а не путями; доступ к папкам проверяется на каждом запросе (чужое — 404). Ярлыки, junction, скрытые и системные файлы, `Restored` не индексируются.
- argon2id; по желанию — второй шаг TOTP (секрет — в `users.json`, повтор кода отвергается). 5 неудач с IP (IPv6 — с сети /64) — блок на 15 мин; больше 50 неудач за 15 мин со всех адресов — вход закрыт для всех, кроме адресов, откуда недавно был успешный вход или ходил клиент бэкапа (клиент бэкапа под этот потолок не попадает).
- Пробуждение ПК вызывает в HA только `script.…`, `button.press` или `wake_on_lan.…`, и задаётся только в `.env`: даже с админкой фотоархива нельзя заставить его вызвать в HA что-то другое (замок, `shell_command`, дополнения); уведомления — только `notify.…`.
- В базе только SHA-256 сессий и токенов. Cookie `HttpOnly; Secure; SameSite=Strict; __Host-`; CSRF — спец-заголовок и Origin; строгий CSP; первый админ — по одноразовой ссылке.
- Запись на ПК: только `RestoreWriter`, только в `Restored`, только файл с хешем, равным эталону файла, который сервер сам пометил повреждённым; путь — из базы сервера, не от клиента; без перезаписи и удаления. Украденный токен позволяет лишь записать подлинное содержимое такого файла; у `photorestore` нет доступа к основной шаре.
- ffmpeg — явный демуксер и белый список протоколов; защита от «бомб» распаковки; запросы мимо прокси — 403. Контейнер: непривилегированный пользователь, read-only FS (кроме `/data`), без capabilities (подробно — «Контейнер: защита и ресурсы»). Токен клиента — DPAPI.
- Репозиторий публичный: `.env`, `data/`, журналы — в `.gitignore`.
