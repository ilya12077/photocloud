# Photocloud

Веб-галерея фото и видео с домашнего ПК: вход → папки, эскизы, лента по месяцам, просмотр с листанием, видео.
Рассчитана на десятки тысяч файлов и медленный интернет у клиента.

> Сейчас MVP: запуск прямо на компьютере, файлы из локальной папки (`STORAGE=local`, только для теста).
> Боевой режим — контейнер на сервере, файлы по SMB с Windows-ПК, пробуждение ПК через Home Assistant.

## Запуск (Windows, Python 3.11+)

```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m app
```

1. Первый `python -m app` создаст `.env` из `.env.example` и остановится. Пропиши в нём `LOCAL_ROOT` и запусти снова.
2. Пока пользователей нет, в консоли появится одноразовая ссылка `http://localhost:8099/admin#setup=…`. По ней создаёшь администратора.
3. Дальше всё через `/admin`: пользователи, привязка Google, сессии, блокировки, настройки, журнал.

ffmpeg для эскизов видео: если в системе есть `ffmpeg` — берётся он, иначе встроенный из пакета `imageio-ffmpeg` (ставится с зависимостями). Свой путь — `FFMPEG=` в `.env`.

Видео с камер (MTS/M2TS/AVI): эскиз и дата есть, в браузере не воспроизводятся — только скачать.

## Что внутри

| | |
|---|---|
| Индекс | обход папок в фоне — сразу после запуска, потом раз в «Пересканировать папки» (`INDEX_TTL`) и когда ПК снова в сети; только имена/размеры/mtime, список в памяти; затем в фоне — даты съёмки |
| Дата | 1) EXIF DateTimeOriginal (JPEG) / creation_time (MP4/MOV); 2) из имени файла — телефоны, WhatsApp, Telegram, скриншоты, Unix-время; 3) год из названия папки; 4) дата изменения. Читаются первые КБ файла, результат кэшируется в SQLite в `data/` |
| Эскизы | на лету в WebP, 3 размера (240/400/900) под фактический размер плитки; на диск не пишутся — RAM-кэш + кэш браузера |
| Список файлов | колоночный JSON + gzip: ~350 КБ на 30 тыс. файлов, повторно — 304 (0 байт) |
| Сетка | виртуальная (в DOM только видимые строки), ползунок по датам; щипок, Ctrl+колесо, Ctrl +/−/0 меняют размер плиток; при быстрой прокрутке картинки не грузятся |
| Просмотр фото | по ступеням: быстрое превью 720 (подпись «Превью •») → 2048 → сразу следом оригинал («Без сжатия •»; при увеличении — без ожидания); недогруженное обрывается при листании, увеличении и выходе; соседние фото подгружаются заранее с низким приоритетом |
| Жесты | вбок — листание с соседним фото; вверх/вниз — фото уменьшается и улетает в свою плитку; щипок и колесо мыши — масштаб; касание живого фото — проиграть ролик |
| Подробнее | смахнуть фото вверх или ⓘ: дата и откуда она взята, файл, папка, размер, разрешение, камера; если в EXIF есть GPS — карта (OpenStreetMap), адрес (Nominatim, кэшируется навсегда) и ссылки на Яндекс/Google Карты |
| Живые фото | фото + ролик с тем же именем в той же папке; сначала лёгкий ролик, следом хороший (до 1080p), при оригинале фото — оригинал ролика; галочка Live (по умолчанию включена, запоминается) — без неё ролики не грузятся |
| Видео | эскиз — кадр через ffmpeg; просмотр — перекодирование на лету в HLS (H.264 720p ~1 Мбит/с), куски по 4 с только в RAM, перемотка работает; галочка «Оригинал» — исходный файл с HTTP Range |
| Доступ | админ видит всё; пользователю можно открыть только выбранные папки (с подпапками) и разрешить или запретить кнопку «Запустить компьютер» — в админке, вкладка «Пользователи» |
| Вход через Google | OpenID Connect + PKCE; войти можно только в аккаунт, к которому админ привязал email |

## Безопасность

- Браузер не видит путей — только непрозрачные id из индекса; path traversal невозможен по построению. Доступ к папкам проверяется на сервере в каждом запросе по id (эскизы, превью, оригиналы, видео, ролики): чужой файл отвечает 404, как несуществующий; список файлов каждому — только из его папок. Ярлыки, junction, скрытые и системные файлы не индексируются.
- Пароли — argon2id; время ответа не выдаёт существование логина. Перебор: 5 ошибок с IP → блок 15 мин, глобальный потолок, уведомление на телефон.
- Сессии: 256-битный токен в cookie `HttpOnly; SameSite=Strict` (+`Secure`, `__Host-` в проде); на сервере только его SHA-256. Смена пароля или удаление пользователя сразу закрывают его сессии.
- CSRF: изменяющие запросы требуют спец-заголовок и проверку Origin. Строгий CSP без inline-скриптов, `nosniff`, запрет фреймов, `no-referrer`.
- Первый администратор — только по одноразовому токену из консоли сервера.
- ffmpeg: демуксер задаётся явно, разрешены только нужные протоколы (защита от «плейлиста под видом .mp4», читающего чужие файлы). Внутренний канал ffmpeg → приложение — только loopback + одноразовый секрет.
- Google: проверяются iss, aud, exp, nonce, email_verified; state привязан к браузеру cookie и одноразов.
- Защита от «бомб» распаковки, лимиты размеров тел запросов, отключены `/docs` и OpenAPI.
- За nginx: `TRUSTED_PROXIES` — реальный IP из `X-Real-IP`, прямые запросы мимо прокси → 403.

Репозиторий публичный: `.env`, `data/` (пользователи, журнал), ключи — в `.gitignore`. В примерах только `example.com` и типовые адреса.

## Сервер (Docker / Portainer на Home Assistant)

В контейнере работает только режим SMB, локальная папка — для теста на компе.

**1. ПК с Windows (откуда берутся файлы)**
- Отдельный локальный пользователь только для чтения, например `photoviewer`, с длинным паролем.
- Общий доступ к папке с фото: Свойства → Доступ → Расширенная настройка → Разрешения: `photoviewer` — только «Чтение», «Все» — убрать.
- Брандмауэр: входящие на TCP 445 только с IP сервера (PowerShell от администратора):
  `New-NetFirewallRule -DisplayName "SMB from HA" -Direction Inbound -Protocol TCP -LocalPort 445 -RemoteAddress <IP_HA> -Action Allow -Profile Private`

**2. Portainer → Stacks → Add stack**
- *Repository*: URL этого репозитория, Compose path `docker-compose.yml` (Portainer соберёт образ сам), или *Web editor* — вставить `docker-compose.yml` и собрать образ заранее.
- *Environment variables* (в репозиторий не попадают):

| Переменная | Пример |
|---|---|
| `SMB_HOST` | IP компа в локалке |
| `SMB_SHARE` / `SMB_SUBDIR` | имя шары / подпапка внутри (необязательно) |
| `SMB_USER` / `SMB_PASSWORD` | `photoviewer` / пароль |
| `ALLOWED_ORIGINS` | `https://<ваш поддомен>` |
| `TRUSTED_PROXIES` | по умолчанию `172.30.32.0/23,127.0.0.1/32` (сеть аддонов HA) |
| `HA_TOKEN` | долгосрочный токен пользователя HA |
| `HA_WAKE_SERVICE` | `script.<ваш_скрипт_wol>` |
| `HA_NOTIFY_SERVICE` | `notify.mobile_app_<телефон>` (необязательно) |
| `PUBLIC_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | для входа через Google (необязательно) |

- Deploy. В логах контейнера появится одноразовая ссылка `…/admin#setup=…` — открыть её через домен (заменив `http://localhost:8099` на `https://<поддомен>`) и создать администратора.

**3. NPM**: Proxy Host → `http`, хост = IP Home Assistant, порт `8099`; SSL + Force SSL + HTTP/2; в Advanced:
```nginx
proxy_set_header X-Real-IP $remote_addr;
proxy_buffering off;
proxy_read_timeout 120s;
client_max_body_size 64k;
```
Проверка: в `/admin` → «Сессии» должен быть ваш внешний IP. Если там IP вида `172.30.x.x` или вход не открывается с 403 — поправить `TRUSTED_PROXIES` под фактический адрес NPM (его видно в журнале «Сессии»/логах).

Контейнер: пользователь без прав, файловая система только для чтения (кроме тома `/data`), все capabilities сброшены, лимит памяти 1.5 ГБ. Данные (пользователи, сессии, кэш дат, журнал) — в томе `photocloud-data`.
